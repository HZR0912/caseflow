# ADR-0002：用服务端 token 映射建立最小可信身份来源

## 问题

请求体携带 user_id、role、tenant 时，客户端能通过改 role 绕过角色策略。
OPA 只能判断给定身份是否有权限，不能证明这个身份属于请求者。

## 决定

W1 的 API 使用随机、不透明的 Bearer token。服务端 AUTH_CREDENTIALS 配置只保存
token 的 SHA-256 摘要及其 user_id、role、tenant 映射；原始 token 由调用方保管。
使用至少 32 字节安全随机数生成 token，不能用低熵口令替代。

两个策略相关接口共用身份依赖：凭据缺失或未知返回 401，并携带 Bearer challenge。
默认凭据表为空；健康检查不要求身份。请求体禁止身份字段和其他未知字段，返回 422。
匹配成功后由服务端构造 PolicySubject，权限决策继续由 OPA 完成。

## 比较过的方案

- 继续接受请求体或 X-Role 等 header：调用者可伪造，不能作为可信来源。
- 立即接入完整 OIDC/SSO：需要配置身份提供方及用户映射，超出本次 W1 修复范围。
- 静态随机 token 映射：无需新增基础设施，能验证鉴权到策略的链路；代价是手动配置、撤销和轮换。

## 边界与后续

这是开发阶段的静态凭据映射，不是企业 SSO，也不实现用户注册、token 签发接口或租户资源隔离。
配置变更后需要重启 API；撤销凭据时删除对应记录并重启。生产接入前替换为
验证签名、issuer、audience 和有效期的身份提供方适配，并部署 HTTPS。
不支持请求体自报身份、身份 HTTP header 或默认管理员作为回退路径。
