# ADR-0003：MockCorp 的持久化、预演与故障语义

## 背景与决定

W2 是一个独立 FastAPI 模拟服务，包含 Identity、Code、Ticket、Money 共 13 个写操作。
它复用已验证的 Bearer 身份解析，以服务端 tenant 作为隔离键；这是内部模拟系统凭据，
并不通过客户端 header 自报租户。Agent 的 OPA、审批、重试与 Saga 编排仍属于后续阶段。

每个模拟租户使用一行 JSONB 状态，包含业务对象、余额、域规则和席位上限。
写操作锁住租户行，业务变更与独立幂等收据在同一事务提交。不同租户可并发，
同租户串行；这对小规模、可复现的模拟环境足够，避免内存缓存重启丢失。
模拟状态表与 W1 的真实业务表隔离，不写入其用户、请求或审计链。

## 契约

- 正式写入要求 Idempotency-Key，作用域是租户；摘要包含操作、路径参数、规范化请求体。
- 同 key 同请求返回首次已提交的状态码和 JSON，附 Idempotency-Replayed=true。
- 同 key 换操作或参数返回 409。fault 不进摘要，允许去掉故障参数后安全重试。
- dry_run 只做相同业务校验并返回 diff；不持久化业务、幂等收据或租户初始化。
  预演不占用 key，不预留资源；预演生成的 ID 不保证正式执行时相同。
- 输入错误、业务拒绝、提交前的 429/500/timeout 不缓存，无副作用，可修正后重试。
- partial_success 仅适用批量分配（至少两项）：确定性地完成前半部分并返回 207，
  结果与成功部分一起持久化；同 key 重放不会继续处理失败项。
- timeout_after_commit 提交成功结果后延迟返回 504，模拟响应丢失。
  重试读取原成功结果；普通 timeout 在提交前返回 504，不产生业务变更。
- 故障默认关闭；显式开启后，各写接口支持通用故障和适配的业务故障。
  不支持的故障组合返回 422；重放已有收据优先于执行新的故障。

## 比较过的方案

- 内存字典：简单，但重启或多 worker 会失去幂等保证；只用于测试中的替身。
- Redis 幂等缓存 + PostgreSQL 状态：两个存储之间存在提交窗口，不能原子提交。
- 每类资源完整关系建模：适合真实系统；本阶段模拟 4 个供应方会扩大迁移成本。

## 代价与复核点

租户行锁、全量 JSONB 更新和无限期收据保留不适合高吞吐生产系统。
W11 大规模评测前按测量结果决定是否拆表或清理测试租户。
MockCorp 只接受虚构数据；密码接口仅递增 password_version，不保存或验证真实密码。
资金使用整数分；退款不得超额，全额退款同时停用该订单关联的席位。
后续 MCP/执行器调用此 HTTP 契约；不会把故障模拟或测试凭据当成真实 SaaS 接入能力。
