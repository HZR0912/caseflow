# ADR-0006：输入护栏——规则先行、可解释、可评测，越权判断不在这里做

- 状态：已接受
- 日期：2026-10-24（W4）
- 相关代码：`core/guardrails/`、`apps/api/main.py`（`/v1/guardrails/check`）、
  `data/guardrails/`、`eval/run_guardrails_eval.py`

## 背景

W4 是第一个"直接面对用户输入"的组件，要做四件事：注入检测、PII 脱敏、
意图分类、槽位抽取。设计方案里还提到第五件——越权预检。

关键约束：**W4 早于 W5 的编排**。此时项目里没有任何模型调用链，
`.env` 里的模型 key 是空的。所以"接一个小模型做分类器"这件事，
在 W4 的时点上没有地方可接。

## 决定一：规则驱动，但检测器是 Protocol（LLM 是未来的替换实现，不是补丁）

注入检测与意图分类都实现成纯函数 + Protocol：

```python
class InjectionDetector(Protocol):
    def check(self, normalized: NormalizedInput) -> InjectionReport: ...
```

W5 之后接 LLM 分类器时，新实现同一个接口即可。规则版不会被删掉，而是降级为
**降级链**——模型超时、限流、供应商挂掉时，护栏不能跟着一起挂。

被否掉的选项：**直接接 DashScope 做检测**。理由不是"模型不好"，而是：

1. 分类器只能给概率，审计日志写不出"拦的是原文第 12–20 字"；
2. 每次跑对抗集都要花钱、要网络，CI 里只能 mock，数字就不可信了；
3. 没有基线就没法证明"接模型之后更好了"——现在规则版是那个基线。

代价：语义泛化弱。同义改写（"上面那些要求都不算数了"）需要专门写规则。
这个代价是**可量化的**：留出集（`cases_holdout.yaml`）第一次跑时，注入类拦截率
只有 0.30，暴露出的正是这个弱点。这些缺口是作为规则补上的，而补之前先记录了数字——
详见下文"留出集"。

## 决定二：归一化只用于匹配，不用于存储

攻击者不需要写「忽略以上指令」。空格插入（`忽 略 以 上 指 令`）、零宽字符、
全角字符、大小写混排、base64 编码都是等价的写法。`normalize.py` 做四件事：

1. NFKC 折叠 + 删零宽字符 + 压缩空白，并**保留原文字符索引**，使命中位置能映射回原文；
2. 二次折叠（去汉字间隔）用于抗空格插入匹配；
3. 对长 base64 串解码后作为**附加文本**再扫一遍；
4. 报告变形痕迹（`zero_width` / `interleaved_separators` / `fullwidth`）用于解释。

第 3 点的关键决定：**解码结果是附加待扫文本，不替换原文**。原文里一段合法的
base64（比如一个 token）不该被改写成乱码。

被否掉的选项：**同形字表**（西里尔 `а` 冒充拉丁 `a`）。覆盖不全的表纯属自我安慰——
它只能防住测试用例里出现的那几个字母。中文业务场景里可预期的是全角/零宽/空白插入，
这四类做了有实际收益。代价：真的遇到同形字攻击会漏，这条写进已知缺口。

## 决定三：PII 是可逆 token 化，不是不可逆涂黑

`PiiVault` 是请求作用域的真实值表，脱敏文本里是 `[EMAIL_1]` / `[PHONE_1]` 这样的
类型化占位符。原因很实际：**办事 Agent 执行时要拿真实值调下游系统**——邮箱要真建，
工单要实名。不可逆涂黑等于让系统在最后一公里拿不到参数。

约束：vault 只存在于内存，生命周期 = 一次请求，不序列化、不落盘。
落库、进日志、进模型上下文的永远只有占位符。

校验位过滤（身份证模 11、银行卡 Luhn）是必须的，不是为了精确性而是为了安全的方向：
没有校验位，`订单号 202610240001234567` 会被误判成身份证，用户可能真的这么写；
下游拿到 `[ID_CARD_1]` 却以为是真实证件号。已知代价：校验位造假的测试身份证会漏。

**不做自由文本人名识别**。中文人名没有词边界，`张伟` 可能是"张开伟岸"的一部分，
自由扫描必然大面积误伤。人名只在槽位抽取阶段处理（`给张三开邮箱`）。

## 决定四：意图是带置信度的路由，阈值来自评测而不是直觉

三档路由：`route`（≥0.55 且与第二名差 ≥0.10）/ `clarify`（≥0.35）/ `human`。

评分分子的选择改过一次，这次改动值得记下来：

初版用「命中权重 / 该意图全部关键词权重」。结果所有正常请求的置信度都在 0.1–0.3，
全部落入 `human`——因为一个意图有十几个关键词，一句话只会命中两三个。
阈值怎么调都救不回来。

改成「命中权重 / 饱和分母 K」，K = 2.0。直觉解释：K 回答"说多少算说清楚"，
阈值回答"多清楚才够放行"。两者分开之后阈值才可调。

两个句式层面的强制规则，都是评测暴露出来的：

- **问句 + 无动作动词 → policy_query**。规则版最容易犯的错是把
  「实习生账号最长多久失效」分到入职准备（「实习生」「账号」都命中了）。系统提示里
  设计方案的原话是"低于阈值转人工"，如果这条被判成入职，Agent 会去开账号。
- **求确认句式（"对吧/我听说/我记得"）→ policy_query，置信度 0.6**。
  「公司规定实习生可以直接开生产库对吧？」里有"实习生""开...生产库"，
  天然会落到入职或权限申请。带着错误前提去办事，比不办事危险得多。
  即使一个制度关键词都没命中（"报销时限是一个月内对吧？"），求确认的句式本身就是
  只读核对请求，不应该转人工。

## 决定五：越权不在这里拦，只打标签

设计方案 §① 写了"越权检测：在护栏层就拦"。**W4 偏离了这个设计**，理由：

1. 项目从 ADR-0001 起就定了"授权只有一个入口 = OPA"。护栏层再做一次权限判断，
   就是两份会各自演化的逻辑——与 ADR-0002 的教训（身份/权限分两处写必然漂移）完全相同；
2. 护栏没有租户数据、没有角色表，做出来的判断只能是"看起来像越权"，
   而误拦一次合法业务请求的代价比漏一个标签高得多。

所以护栏的产出是 `risk` 标签（`grant_admin` / `batch_change` / `destructive` /
`data_export`）和 `policy_action`（数据外泄类直接映射到 `data.export`）。
**真正的拦截在 W5 接 OPA 时验证**。代价：W4 的演示里看不到"越权被拒 403"，
只能看到风险标签——这个演示要等 W5。

## 决定六：对抗集分两份，一份只许跑一次

`cases.yaml`（60 条对抗 + 30 条正常）是和规则一起迭代的。看到失败就改正则，
跑出 100% 拦截率只证明"规则记住了这 60 句话"。

`cases_holdout.yaml`（25 条对抗 + 10 条正常）是为了回答"没见过的攻击能不能防住"。
流程约定：写完的第一版跑一次并记录数字，**之后不以此为调参目标**。

第一次的记录（2026-10-24，规则版 v1）：

| 指标 | 调参集 | 留出集 |
|---|---|---|
| 危险操作拦截率 | 1.000 | **0.385** |
| 误拦率 | 0.000 | 0.000 |
| 意图路由准确率 | 0.767 | 0.900 |

差距就是规则泛化能力差的直接证据。之后补的规则（`override-variants-zh`、
`role-escape-jailbreak` 的变体、「以…身份命令」、`param-script`）是为了**覆盖类别**
而不是为了刷这 25 条，改完后调参集回归仍然 1.000。留出集现在的数字是 1.000，
但必须承认它**已经被看过**，不再是严格意义上的留出集——真正的留出集需要下一批。

## 已知缺口

2026-10-24 修复复核：上文旧留出集现保存为 `cases_regression_v1.yaml`，
`cases_holdout.yaml` 已替换为 v2（25 条对抗 + 15 条正常）。规则冻结后首测拦截率
10/13 = 0.769，误拦 0/15；没有依据其失败调整本轮规则。详情见
[实测记录](../benchmark.md) 与 [验收步骤](../w4-fixes-verification.md)。
负责人按角色变更语境识别；新增 sensitive_data、rights_claim 只标记信号，不作授权依据。

- 语义级改写（换掉全部关键词、只保留攻击意图）规则版一定漏。这是接 LLM 分类器的
  直接理由，也是 W5 的验收点之一。
- 同形字攻击（西里尔字母冒充拉丁）未处理。
- RAG 检索来的**文档内容**里的注入（间接注入）完全没有覆盖——W5 接 RAG 后必须补，
  而且这次的教训是：文档内容不走 `/v1/guardrails/check`，需要一条独立的扫描路径。
- 槽位抽取的日期/人数识别是正则，`两周后`、`半个月` 这类表述不支持。
- 留出集规模 25 条，统计意义有限；数字的变化趋势比绝对值更可信。

## 复核点

1. W5 接入 LLM 分类器后，用同一份调参集对比：置信度分布、拦截率、误拦率、
   **单次调用延迟与成本**。规则版永远保留为降级链。
2. 接入 RAG 后立刻补间接注入的扫描路径（检索到的 chunk 进模型前过一遍检测）。
3. 若规则数量超过 25 条或单条正则超过 150 字符，说明该换分类器了——
   规则的可维护性按条数线性下降。
