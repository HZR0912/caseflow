# ADR-0007：W5 understand → plan → dry-run

- 状态：接受
- 日期：2026-10-24

## 范围

LangGraph 串起 understand → retrieve → plan → authorize → dry_run。
先支持入职准备的四类动作：账号、邮箱、仓库邀请、入职工单。三人生成 12 步 DAG。
不支持的办事意图转人工，不猜工具；制度问答返回经校验的原文证据。
W6 才实现审批 interrupt 与持久化会话的恢复接口，W7 才执行正式写入。

## 决定

1. 计划是 Pydantic 契约，操作白名单、依赖存在性、无环和结果引用均校验。
   规划模板固定业务依赖；自然语言解析是可替换接口，规则版可离线演示。
   可选 Qwen/DeepSeek JSON 槽位解析按顺序降级，最后退回规则；只补充有原文依据的
   缺失槽位，不能覆盖已有事实、发明员工或更改工具 DAG。真实付费模型尚未验收。
2. 身份只来自 API Bearer 凭据映射。每个实际动作由 OPA 授权，admin 权限额外检查
   admin.grant；不信任用户或模型提供的风险标签。OPA 不可用则停止。
3. 单步 dry-run 不保留新资源，不能直接用其虚拟 ID 预演后续动作。因此增加仅预演的
   `/v1/preview`：在 MockCorp 同一事务私有状态中按拓扑顺序运行现有业务校验，最终
   persist=False，丢弃业务和收据，只提交一条 plan.preview 操作日志。
   独立分支继续预演，失败分支的后继 skipped；发现冲突返回追问，不谎称预演成功。
4. 不给预演资源 ID 作正式执行保证。状态变化后预演可能过期，正式执行必须重检。
5. 请求原文和 PII vault 留在请求作用域，不写入图状态；计划与 diff 返回前脱敏。
   可选 checkpointer 仅接收脱敏状态。W5 HTTP 不承诺跨请求的 vault 恢复。
6. 制度是证据，不是授权。检索文本先扫描间接注入，再逐字校验引用；不能拿一段
   制度覆盖工具约束或 OPA。当前 MockCorp 没有权限到期自动回收能力，计划明确列为
   待实施约束，不把生成工单描述成已实施定时回收。

## 代价

W5 不是通用自主规划器；模板范围外明确转人工。每人 4 步是由业务依赖得到的，
不是为了所有请求都输出 12 步。服务端 preview 使用现有事务业务逻辑，不代表外部
真实 SaaS 必然支持多步事务预演。PII、临时 ID 与状态漂移使 W6/W7 必须重做执行校验。
