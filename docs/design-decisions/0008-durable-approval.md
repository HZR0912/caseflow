# ADR-0008：持久化审批与中断恢复

- 状态：接受
- 日期：2026-10-24

## 决定

W5 的请求闭包含未持久化的真实姓名和账号，不可伪装成可跨进程恢复的图。
W6 在成功预演后创建不可变、已脱敏的审批快照，作为独立持久化图的输入：
`review → approval(interrupt) → report`。PostgresSaver 保存每个节点，审批等待中
杀掉进程后以相同服务端 thread_id 恢复；不重跑 W5。只有经过服务端 W5 预演的结果
可以提交，客户端不能自行提交 plan、tenant、role 或 checkpoint_id。

审批表保存快照、摘要、申请人、期限和唯一决策；checkpoint 保存执行进度。
二者不是一个数据库事务，因此采用可恢复的决策日志：先提交不可变决策，再向图发送
Command(resume)。崩溃后读接口/恢复接口可观察未完成状态，相同决策重试或 recover
继续；若图已完成但投影未更新，从 checkpoint 修复。没有“恰好一次跨系统事务”的承诺。
PostgreSQL 会话级 advisory lock 串行化同一审批单的 start/resume/recover，竞争请求
返回 409；会话断开自动释放锁。创建使用租户+申请人+Idempotency-Key 防重复。

审批快照整体计算 SHA-256，决定必须携带一致的 plan_hash。过期或已变更版本拒绝审批；
审批人必须经当前凭据与 OPA 授权，且不能是申请人。同租户查询由所有权和 OPA 控制，
跨租户统一 404。决策绑定可信审批人、理由、时间与唯一操作 ID；拒绝必须说明理由。
审批意见脱敏，不把 token、员工原文写入 checkpoint。浏览器 token 只存在内存。

## 边界

W6 的 approved_ready 表示审批记录已完成，不触发正式工具写入。
脱敏审批快照不能直接用作 W7 执行参数；W7 必须引入安全的实体恢复机制并重检授权、
期限和资源状态。等待期间不维护原始 PII vault，也不保存 Bearer token。
W6 不提供计划原地编辑；更正后提交新版本并重新预演审批。W5 预演完成前的中断不在
本周跨进程恢复承诺中。审批台使用 Vue 3 / TypeScript / Vite，主 API 同源提供构建产物。
