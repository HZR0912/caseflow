# ADR-0010：冻结分组的持久 Saga 与收据绑定补偿

- 状态：接受
- 日期：2026-10-24

## 问题

W7 遇到业务失败后停止，已完成工作没有处理路径。全局回滚会错误撤销已完成的身份准备，
批次中只有部分工单分配成功时也不能把整个批次当成成功或失败。补偿本身可能超时、崩溃或被拒。

## 决定

新计划版本 1 在审批前冻结 saga_group；失败只补偿同组成功步骤，按执行顺序逆序。
组外或不可逆成果保护其依赖，未知正向结果先人工对账。沿用 execution_runs JSONB，
保存独立补偿列表、固定键、次数、事件和重试时间，不新增第二套状态表。
补偿与正向执行共享审批锁，每次撤销重新检查 OPA。

供应方从原幂等收据读取 before/after，租户锁内先比较全部对象，再原子撤销并写补偿收据。
补偿键只能是原键的确定性派生值。退款使用金额增量，批次仅撤销原 diff 中的成功项。
原始正向结果与最终影响摘要并存，禁止用“回滚成功”冒充任务成功。

## 未采用的选项

- 整租户快照回滚：会覆盖无关业务写入与并行员工成果。
- 客户端提交撤销参数/before-image：容易扩大范围、篡改金额和跨对象撤销。
- 内存补偿栈：退款提交后进程退出会丢进度，重试预算也会重置。
- 对所有失败自动补偿：不能证明超时操作未提交，可能破坏仍在运行的依赖。

## 代价与复核点

模板分组由开发者明确设计，未来支持自由计划时需额外验证业务范围。
MockCorp 每租户串行写入，吞吐有限；CAS 当前比较对象值而非版本，不检测 ABA。
终态人工处理尚无自动核对/结案工作流。长等待需要显式恢复。
真实外部系统接入前必须逐个确认幂等、可逆性、版本校验与资金退款契约，
不能把本地模拟器的原子语义推广为任意第三方 exactly-once。
验证证据见 [W8 报告](../w8-verification.md)。
