# ADR-0011：显式、分层、可遗忘的记忆与关系型组织目录

- 状态：已接受
- 日期：2026-10-25

## 背景

W5–W8 已把完整单次申请串到预演、审批、执行和补偿，但重复办事仍需要重复填信息。
直接把历史聊天拼进提示词会混淆本次修正、旧偏好、组织事实与授权依据，
并使 PII、过期数据和跨用户信息难以隔离。

## 决定

1. 三类数据分别存储：会话使用 LangGraph PostgreSQL checkpoint；
   个人偏好使用 PostgreSQL + pgvector；组织使用关系表和递归 CTE。
2. 显式选择召回。本次输入覆盖会话，后者覆盖个人偏好，最后才用组织默认值。
   只有用户确认的白名单偏好能长期保存，分数按固定半衰期衰减。
3. 会话槽位加密并绑定 tenant / owner / session，返回脱敏；
   不持久化自由文本聊天，所有 checkpoint 操作先检查会话所有权。
4. 偏好与会话使用版本和 advisory lock，组织用版本 + 单租户事务替换。
   偏好遗忘仅保留空内容修订元数据，避免删除后重建的 ABA 误操作。
5. 组织里保存部门负责人、主管、导师和系统归属，不保存认证角色。
   所有业务动作继续由 OPA、预演和审批控制。
6. 提交时冻结来源版本；旧审批不随目录或偏好变化。个人历史和同部门历史只提供结果摘要。

## 没采用的选项

- 全聊天自动长期入库：难以确认意图、修正、保留期限和敏感信息边界。
- 用组织职位推导管理员角色：混淆业务关系和认证授权。
- 单一向量库承载部门关系：无法可靠验证环和引用、无法保证确定的继承顺序。
- 引入独立图数据库：当前关系规模可由 PostgreSQL 递归查询解决，增加服务没有必要。
- 自动从历史批准推导新默认权限：旧批准绑定旧计划，不能作为新操作授权。

## 代价与复核点

当前只有五类结构化偏好，HashingEmbedder 只提供词面召回，不提供自由语义记忆。
同部门历史采用明确字段匹配和时间排序，没有跨流程语义相似度模型。
组织完整快照替换适合开发阶段；规模扩大或多人维护时需增量编辑、变更审计和 HR 同步。
会话密钥仍复用执行密钥，企业上线需密钥轮换、备份保留和清除策略。
过期物理清理没有后台调度；恢复靠会话 ID，尚无跨会话搜索 UI。
这些需求出现时复核模型与存储设计，不用当前试验规模推导生产性能。
