# ADR-0012：显式 OTel、独立持久回放与可选 Langfuse

状态：已接受。日期：2026-10-25。

## 问题

规划、人工审批和执行跨请求、跨进程；单条日志无法解释重试与补偿。直接采集模型与工具原文又会复制员工资料和凭据。

## 决策

使用显式 Span 和安全结构投影。由租户与服务端申请 ID 得到稳定 Trace ID，合成父级关联多个阶段，不用持续数天的活动 Span 表示审批等待。PostgreSQL 单独保存开始/结束帧，业务状态仍以审批及执行 journal 为准。通过异步批量 OTLP 导出到通用 Collector 或 Langfuse。读取回放必须经过认证、OPA 和 tenant/owner SQL 条件，不提供重执行端点。

## 代价与替代方案

每个帧额外写数据库，增加小流量场景的耗时；业务库共用基础设施并非故障域隔离。采用短连接超时与失败冷却控制影响，后续需要压测再决定池化或异步持久队列。

没有采用自动采集全部 HTTP 正文/LLM prompt，因为会泄露数据；没有只依赖 Langfuse，因为离线和进程强杀时本地仍需解释执行经过；没有让观测写失败阻止业务，因为观测不是执行一致性的来源。放弃无损导出承诺：内存队列没有重启后补传保证。

## 复核点

出现高并发、长期留存、多业务服务或审计合规要求时，复核写入开销、租户级 Langfuse 项目隔离、数据保留、采样与持久 outbox。缺少模型用量或价格时继续显示未知，不以零值代替。
