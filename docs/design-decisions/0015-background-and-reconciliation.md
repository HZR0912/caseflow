# ADR-0015：持久执行授权、后台接续与收据对账

日期：2026-10-25。状态：已接受。

## 背景

执行器已有幂等键、重试预算、分组补偿和崩溃恢复，但长等待后仍依赖人再次点击；
补偿结果不确定时，也缺少核对真实影响和记录处理决定的入口。

## 决定

1. 只有人在批准计划上显式执行，才保存后台授权。PostgreSQL 保存授权、到期时间、
   任务状态；Redis/Arq 只发送审批 ID。周期扫描可重建丢失的消息，重复消息沿用请求锁和原幂等键。
2. API 可先同步执行；等待或进程中断后由独立 worker 接续。授权密文绑定租户、审批、
   计划哈希、操作者、角色和期限，每次外部写操作前复核身份与 OPA 权限。
   真实拒绝或授权失效会暂停；基础设施暂不可用使用有上限的后台重试。
3. API、worker、对账、结案共用审批 advisory lock。后台接续不能重置业务重试预算，
   不能自动接手只有审批通过而没有执行授权的单据。
4. 对账同时读取供应方幂等收据、补偿收据和当前实际状态。证据绑定原执行日志和有效期，
   结案时重新读取供应方，变化或过期则要求再次核对。
5. 人工决定分为确认本组补偿、接受当前已观测状态、继续待处理。缺收据且结果未知时
   只能继续待处理。结案单独保存并冻结后续执行，不把原失败日志改写成成功。

## 取舍与代价

- 放弃只用 Redis 队列保存任务：消息丢失不能意味着丢失办理义务。代价是周期扫描和
  重复唤醒；PostgreSQL 与请求锁仍是可用性关键依赖。
- 放弃给 worker 一个跨租户万能身份：接续使用原执行人的有期授权。代价是服务端必须
  加密保存可用凭据，并要求 API、worker、供应方同步更新身份配置与稳定加密密钥。
- 放弃缺收据即视作未执行：远程请求可能迟到。代价是某些未知结果必须保持待处理；
  真正解除这种情况需要供应方提供取消屏障或终局查询协议，当前未实现。
- 采用核对时点证据，不承诺供应方状态永久不变。供应方在核对后仍可被其他系统修改，
  结案只表示有权限的人接受了本次观察结果。
- 后台运行需独立 worker 与 Redis；页面提示接续不等于 worker 活性证明。当前没有
  独立 worker 运行告警、集中撤权平台或生产容量承诺。

## 复核点

接入真实企业 SSO/供应方、扩展 worker 数量、启用长期任务或增加跨系统结案规则时，
重新评估授权续期、凭据轮换、供应方迟到请求、锁范围、审计保留和监控告警。
验证结果见 [后台恢复](../w12-background-recovery-verification.md) 与
[异常对账](../w12-reconciliation-verification.md)。
